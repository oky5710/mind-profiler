# UI Style

색상 토큰 자체는 [design-system.md](design-system.md) 참고. 이 문서는 레이아웃/타이포/차트를 그리는 방식의
**목표 규칙**이다 (지금 코드가 아래 규칙을 전부 만족하는 건 아님 — 실제 구현 상태는 [features.md](features.md) 참고).

## 공통

- 화면 최상단은 `NavigationStack` + `.navigationBarTitleDisplayMode(.inline)`.
- 로딩 상태는 `ProgressView()`보다 `HeartLoader`(하트 박동 애니메이션)를 우선 사용 — 로딩이 오래 걸릴 수 있는
  화면(HealthKit/네트워크 동시 로딩 등)에서 통일된 느낌을 준다.
- 에러 메시지는 화면을 막지 않고, 해당 에러와 관련된 UI가 있는 자리(제목 위가 아니라 그 UI 바로 위/아래)에
  `.font(.footnote).foregroundStyle(.red)`로 노출한다 (AGENTS.md 규칙: 에러는 숨기지 않고 UI에 노출).
- 접근성: VoiceOver 등으로 화면의 모든 정보를 읽을 수 있게 한다.
- 앱은 세로 화면만 지원한다 (`Info.plist`의 `UISupportedInterfaceOrientations`) — 가로 회전을 전제로 한
  레이아웃을 만들지 않는다.
- **버튼 안에서는 줄바꿈하지 않는다** — 아이콘+글자든 뭐든 버튼 하나의 내용은 항상 한 줄(`HStack`)로
  유지한다. `Text`가 자동으로 여러 줄로 꺾이는 것도, 내용을 `VStack`으로 나눠서 억지로 두 줄짜리
  버튼을 만드는 것도 안 된다. 여러 버튼을 한 줄에 늘어놓았을 때 폭이 부족하면, 버튼 내용을 줄이는
  대신 버튼째로 다음 줄로 내린다(`ViewThatFits`로 한 줄 배치가 안 맞으면 여러 줄 배치로 자동 전환 —
  `HomeView`의 커피/약 버튼 참고).
- **`Typography.sectionTitle`** 아래 여백은 16pt로 고정한다 — 나머지 방향(좌우/하단)의 기본 여백은
  그대로 두고 제목 바로 아래만 16pt로 맞춘다(`ReportView`의 각 섹션, `HRVAnalysisView`의 "HRV Trend" 참고).
- **`Typography.screenTitle`(네비게이션 바 타이틀)** 아래 여백은 10pt로 고정한다 — 나머지 방향
  (좌우/하단)의 기본 여백은 그대로 두고 상단만 10pt로 맞춘다. `ScrollView`/`GeometryReader` 기반
  화면은 콘텐츠 컨테이너에 `.padding(.top, 10)`(다른 방향은 `.padding(.horizontal)`/`.padding(.bottom)`
  로 유지), `List` 기반 화면은 `.contentMargins(.top, 10, for: .scrollContent)`를 쓴다(`SettingsView`,
  `HRVAnalysisView`, `CalendarView`, `ReportView` 참고). `HomeView`의 `screenTitle`은 네비게이션 바
  타이틀이 아니라 사진 위에 겹쳐 그리는 문구라 이 규칙의 대상이 아니다.

## 차트 (Swift Charts)

### 성능
- 화면에 보이지 않는 구간까지 매번 다시 계산하지 않는다 — 스크롤/모드 전환 시마다 전체 데이터를 다시
  스캔하면 느려지므로, 범위 계산 같은 무거운 연산은 데이터·모드가 바뀔 때만 캐시해서 갱신한다.

### 여러 지표를 그릴 때
- **y축 단위가 다른 데이터는 겹쳐 그리지 않는다** — 예: HRV 값 vs 수면/운동 구간은 반드시 별도의 `Chart`
  인스턴스로 분리한다. 하나의 y축에 억지로 맞추면 가짜 눈금 값이 생긴다.
- **여러 Chart를 세로로 쌓아 하나처럼 보이게 할 때, x축 눈금 위치는 반드시 동일해야 한다.** Swift Charts의
  자동 눈금 계산에 맡기면 차트마다 다른 위치에 그려질 수 있으므로, 눈금 `Date` 배열을 직접 계산해서
  모든 차트의 `.chartXAxis`에 동일하게 적용한다. 줌/스크롤이 있는 화면(`HRVAnalysisView`)은 네이티브
  축을 숨기고(`.chartXAxis(.hidden)`) 커스텀 오버레이로 직접 그리는 무거운 방식을 쓰지만, 고정된 기간만
  보여주는 화면(`ReportView`의 수면/CV 차트)은 그 정도까지 필요 없다 — `AxisMarks(values:)`에 공유
  눈금 배열만 넘기고 네이티브 렌더링은 그대로 쓴다. 어느 쪽이든 그리드 `.gray.opacity(0.25)`/틱
  `.gray.opacity(0.85)`/라벨 9pt(`tracking(1)`)는 동일하게 맞춘다(아래 "축 / 눈금" 참고).

### 크기
- 주 차트(HRV 라인/월별 막대)의 높이는 화면 전체 높이의 40%로 한다.
- 같은 x축을 공유하는 보조 차트(예: 수면/운동 Gantt 레인)는 주 차트 높이의 절반의 70%(= 주 차트의 35%)로 한다.

### 축 / 눈금
- 그리드 라인(`AxisGridLine`)은 옅게, 눈금 틱(`AxisTick`)은 그보다 진하게 — 그리드보다 축 자체가
  도드라져야 읽기 편하다. 그리드 라인은 최소한만 그린다(눈금마다 다 그리지 않고, 축을 읽는 데 필요한 개수만).
  - 예시: 그리드 `.gray.opacity(0.25)`, 틱 `.gray.opacity(0.85)`.
- x축은 눈금마다 그리는 세로 그리드(옅게, 그리드 색)와 플롯 하단을 가로지르는 축 기준선(진하게, 틱 색)을
  구분한다 — 세로 그리드를 진하게 하면 안 되고, 기준선만 진하게 한다.
- 같은 x축을 공유하는 차트를 세로로 여러 개 쌓을 때(라인 차트 + Gantt 레인)는 차트 사이 레이아웃
  여백을 아예 두지 않는다(`VStack(spacing: 0)`) — 여백을 두면 위 차트의 축 기준선과 아래 차트의
  축 기준선 사이에서 Gantt 막대를 정중앙에 두는 계산이 그 여백만큼 더 복잡해지고, 세로 그리드도
  그 틈에서 끊겨 보여 이어주는 선을 따로 그려야 했다. 간격이 없으면 그리드도 자연히 이어지고,
  Gantt 차트 안에서 위아래 대칭으로 여백(현재 4pt)만 주면 그대로 두 기준선 사이 정중앙이 된다.
- 축 라벨 폰트는 작게(예: 9pt), 단위(일/월/년 등)가 바뀌는 지점은 `.bold()`로 강조한다.
- y축 라벨은 차트 안에서 자리를 차지하지 않고 고정된 위치에 표시한다.
- y축은 0부터 시작하고 고정 간격(예: 50 단위)으로 그린다 — 데이터 min/max에 맞춰 축을 움직이면 값이
  실제보다 과장되어 보인다.
- x축 라벨은 서로 겹치지 않게 하고, 라벨 간 간격이 실제 라벨 텍스트 너비(예: 9pt "MM-dd"/"HH:mm" 기준
  약 40px)보다 좁아질 것 같으면 일부를 생략한다 — 틱 위치만 보고 최소 간격을 너무 좁게(예: 10px) 잡으면
  틱은 안 겹쳐도 텍스트는 겹쳐 보인다. 생략하더라도 같은 단위(예: 전부 "시:분" 또는 전부 "월-일")로
  통일해서 표시한다. 이 간격은 확대/축소(핀치 줌 등)로 눈금 밀도가 바뀌어도 매 렌더마다 다시 계산되어야
  한다.
- 위아래로 쌓인 두 차트가 각자 x축 라벨을 보여줄 때는 방향을 반대로 둔다 — 위 차트(예: 라인 차트)의
  라벨은 플롯 안쪽 위로, 아래 차트(예: Gantt 레인)의 라벨은 플롯 바깥 아래로 붙인다(`xAxisLabelBelow`).
  둘 다 안쪽에 두면 차트 사이 좁은 공간에 라벨이 몰리고, Gantt 막대의 여백 자리와도 겹쳐 보인다.
- x축 세로 그리드는 "정시"에만 찍는다 — 일별 모드는 자정(00시)에만, 시간별 모드는 분이 00일 때만.
  스크롤 위치(임의 시각) 그대로 일정 간격을 더하면 14:23처럼 어중간한 시각에 눈금이 생기므로,
  시작점을 가장 가까운 깨끗한 경계로 올림(ceiling)한 뒤 그 경계 단위로만 전진한다.

### 날짜 표기
기본 형식은 `yyyy-MM-dd HH:mm:ss`이며, 인접한 두 데이터 포인트 간 시간차에 따라 축약한다:
- 하루 미만 차이 → `HH:mm`
- 하루 이상 30일 미만 차이 → `MM-dd`
- 30일 이상 차이 → 월만(`M월`) 표기

### 스크롤 / 인터랙션
- 가로 스크롤은 Swift Charts 내장 `.chartScrollableAxes`가 아니라 `DragGesture` + `.chartOverlay`로
  직접 구현한다 — 내장 스크롤은 다중 Chart·커스텀 x축 조합에서 반응하지 않는 경우가 있었다. 스크롤은
  "지금 이후"로는 이동하지 못하게 클램프한다.
- 차트를 드래그/탭하면 그 x축 위치에 대응하는 y축 값을 함께 보여준다 (툴팁 형태). 값 하나가 아니라
  여러 필드(제목/시간/장소, 단계별 구성 등)를 보여줘야 하면, 좁은 차트 안에 띄우지 않고 차트 아래
  전체 폭 카드로 보여준다 — 흰 배경 + 옅은 테두리 + 그림자(라이트 모드에서도 잘 보이게), 오버레이로
  그려서 레이아웃 높이에는 영향이 없게 한다 (`HRVAnalysisView`의 `selectedItemDetailPanel` 참고).
- 드래그로 스크롤하는 동안(이동량이 일정 이상)은 툴팁/상세 패널을 감추고, 이동이 거의 없는 탭일 때만
  갱신한다 — 스크롤과 툴팁 갱신이 뒤섞이면 산만해진다.
- 선택된 항목을 강조해야 하면(Gantt 막대 등), y축 범위나 마크 크기를 바꿔서 "커 보이게" 하지 않는다 —
  차트 전체 높이가 선택 여부에 따라 달라 보이는 착시가 생긴다. 대신 그림자를 준다(차트 마크 자체는
  `.shadow()`를 지원하지 않으므로, 같은 위치·크기·색의 실제 SwiftUI 도형을 겹쳐 그려서 그 도형에
  그림자를 적용한다).
- Gantt 막대는 `.cornerRadius(4)`로 모서리를 둥글린다.
- 핀치 줌(`MagnificationGesture`)은 값(시간)만 계산하면 되고 `ChartProxy`가 필요 없다는 점을 이용해서,
  같은 x축을 공유하며 세로로 쌓인 여러 `Chart`(라인+Gantt 등) 중 하나가 아니라 그 전체를 감싸는 상위
  컨테이너에 `.simultaneousGesture`로 한 번만 붙인다 — 각 차트 자신의 드래그 오버레이 안에 붙이면
  두 손가락이 서로 다른 차트 위에 떨어졌을 때 하나의 핀치로 인식되지 않고, 각 차트가 손가락 하나짜리
  드래그로 오인해서 스크롤과 뒤섞인다(`HRVAnalysisView+Axes.swift`의 `magnifyToZoomGesture` 참고).
  배율 한계에 닿으면 화면 흔들림 대신 토스트로 알린다(아래 "토스트" 참고).
- 하단에 범례를 두고, 범례 항목을 탭하면 해당 지표를 차트에서 보이기/숨기기 토글한다. 숨긴 항목은 범례에서
  투명도를 낮춰 "꺼져 있음" 상태를 표시한다.
- 차트(라인+Gantt 또는 캔들스틱+CV)와 범례 사이는 나머지 요소 간 기본 간격(8pt)보다 넉넉하게
  26pt를 띄운다 — 아래 차트의 x축 라벨이 플롯 바깥으로 나와 있어서, 기본 간격만으로는 라벨과 범례가
  붙어 보인다.

### 범례 레이아웃
- 범례는 `LazyVGrid`(2열)로 배치하고, 항목 하나가 한 칸(cell)이 되게 한다 — 한 지표가 스와치를 여러
  개 쓰더라도(예: 월별 캔들스틱의 박스/중앙값/최소~최대), 한 칸 안에 여러 줄을 욱여넣지 않고 각 스와치를
  독립된 칸으로 나눠서 다른 항목들과 같은 그리드 흐름으로 좌측 정렬되게 한다.
- 같은 칸 안에서 "스와치(사인) + 글씨" 구조일 때, 글씨가 나오는 세로 위치는 모든 항목이 서로 맞아야
  한다 — 스와치 실제 크기가 서로 달라도(원형 아이콘 8pt, 얇은 세로선 10pt, 굵은 가로선 2pt 등) 모두
  같은 너비·높이의 칸 안에 넣어서 텍스트 세로 위치가 항목마다 어긋나지 않게 한다.
- 스와치를 담는 칸의 너비는 범례 전체에서 통일한다 — 스와치 자체는 그 너비 안에서 가운데 정렬로 표시한다
  (예: 12pt 너비 칸에 8pt 사각형이나 2pt 세로선을 가운데 정렬).

## 인터랙션 (화면 전체)

- 간편 입력(홈 화면의 기분/커피 등)은 탭 한 번으로 끝나야 한다 — 폼을 열지 않고 바로 기록.
- 상세 입력(캘린더 날짜 탭)은 bottom sheet로 열어서 유형 선택 → 폼 순서로 진행.

### 토스트
- 짧게 떴다가 자동으로 사라지는 안내는 화면마다 따로 구현하지 않고 공통 `ToastCenter`
  (`Components/Toast.swift`, `@Environment(ToastCenter.self)`)의 `show(_:type:)`를 쓴다.
- 유형은 세 가지뿐이다 — 정보(`.info`, 파랑 아이콘): 값의 한계·상태 변화 등 중립적 안내. 성공
  (`.success`, 초록): 사용자 액션이 정상적으로 끝났을 때. 에러(`.error`, 빨강): 액션이 실패했을 때.
  배경(검정 반투명 캡슐)과 텍스트 스타일은 세 유형이 모두 같고 아이콘 색으로만 구분한다 — 유형별로
  배경색까지 바꾸면 화면마다 톤이 흔들린다.
- 폼 검증 실패처럼 사용자가 계속 보고 있어야 하는 오류는 토스트(자동으로 사라짐)가 아니라 기존처럼
  화면에 남는 `Text(...).foregroundStyle(.red)` 오류 문구를 쓴다 — 토스트는 "지금 이 순간 일어난 일"을
  잠깐 알리는 용도지, 사용자가 액션을 취할 때까지 남아 있어야 하는 오류에는 맞지 않는다.
